## Decision record and carry-forward

- Preserve the existing authority, ProjectOS artifact heads, durable job fencing, tenant/project boundaries, typed contracts and fail-closed effect gates. No new, competing approval authority. The durable tick is **at-least-once**; a persistent worker is not deployed.
- The approved-brand → UCPO bridge, transactional SQLite path, selective dependencies, and source/build/QA/proof freshness guards exist. Disposable PostgreSQL 16 tests now observe advisory-lock waits for same-key replay, different-key site revisions and an in-flight synthetic build versus a revision. This is a narrow local result, not full PostgreSQL/Supabase concurrency coverage. The positive proof-origin test uses explicitly synthetic dispatch; an actual pinned-browser proof remains open.
- Finite deliverable expectations exist, but client-provided quantities or a candidate's artifact list are not trusted evidence. Blocking declarations stay `NOT_MEASURED`/`ESCALATE` until server-owned inventory, evidence, rights and acceptance are bound.
- VNEXUS cached-operation replay now has an explicit, fail-closed operation matrix and rechecks present source/target/scope access. Project-scoped brand resolution, readiness, branch comparison and twin child-scope summaries also gained source checks. A reproduced brand-graph cross-project disclosure led to a restrictive interim guard: graph access, brand-wide twin views and immune scans require tenant-wide (`*`) project access as well as brand-owner access. Do not grant wildcard access merely to bypass it. These are local mitigations, not proof of global isolation: per-node project binding, other cache/effect systems and permission-change races still need independent review, and replay can be stricter than an original project-only write.
- Fictional Northline web builds and procedural media are **demonstrations**, not customer approval or a finished campaign. The contact anchor deliberately has no form, message destination or lead capture, so this is not a complete buyer journey. Media QC is technical; rights, implicit fonts, creative quality, accessibility and release are separate. Pinned Chromium website QA remains blocked. Dissolves overlap title layers and caption visibility uses estimates.
- Maintain disabled or explicitly unavailable providers. No publish, deploy, spend, customer contact or external transfer is implied by this plan. A local test, mock, simulated approval or alternate browser cannot satisfy a real external or canonical gate.

## Planning assumptions, resources and estimates

These are **proposed targets, not committed dates or assignments**. No people have been assigned or availability confirmed. Effort below is rough **person-days**, excluding procurement, provider onboarding and unbounded creative iterations; ranges are additive estimates across workstreams and include ordinary code review but not external waiting time. The total is approximately 274–424 person-days; specialist bottlenecks, holidays, integration and contingency can extend the calendar beyond a simple division by headcount. Dates assume work can start 2026-11-10 and roughly 5.5 engineering/test FTE are available: two backend/security engineers, one frontend/accessibility engineer, one media engineer/editor, one QA/integration engineer and a half-time SRE. A technical lead coordinates architecture/review; product owner, brand/client representative, legal/rights reviewer and independent approver contribute part-time. Staffing and holiday schedules must be confirmed before treating targets as commitments. Each role is a required capability, not a claim a person is working on the project.

Complexity is a rough planning band: **S** ≤3 person-days; **M** 4–10; **L** 11–20; **XL** >20 or cross-system/authority risk. Estimates may straddle band boundaries. Priorities: **P0** blocks safety, integrity or any credible release; **P1** is required for full product acceptance; **P2** follows safe end-to-end operation. A target date is the planned end of that workstream, not evidence of completion. `BLOCKED` rows may slip without changing the release gate. Tasks within a row can be split into reviewed increments; estimates are not a promise that parallel work has no integration cost.

## Risks, triggers and contingencies

| Risk / likelihood / impact | Trigger and contingency |
|---|---|
| Pinned browser unavailable / high / high | Browser install cannot run on the current host. Run on approved CI or a permitted host; keep canonical QA and release `BLOCKED`. A diagnostic browser is not a substitute. |
| Trust-boundary or source-inventory gap / high / critical | A count, hash, licence string or empty source list is caller asserted. Return `NOT_MEASURED`, require server-derived, scoped inventory and independent security review; do not approve around it. |
| Cross-project graph or replay disclosure / high / critical | Brand graph nodes do not uniformly carry an independently enforced project binding, and other idempotency implementations have not been audited. Keep multi-client release blocked; define sharing, enforce source/target rights at every path, test revocation/races and require independent review. |
| Cross-worker races or crash replay / medium / critical | Concurrent commits, reservations or retries differ across databases. Stop activation, add PostgreSQL fault-injection and fencing/settlement tests, reconcile or roll back. |
| Sandbox escape/resource exhaustion / medium / critical | Untrusted render/build reaches host files, network, PID state or uncontrolled CPU/memory. Block execution, add OS isolation and an independent review; Blender stays blocked until equivalently isolated. |
| Creative/accessibility defects / high / high | Overlapping dissolve titles, unreadable text, estimated cue timing or missing audio. Repair and re-render; require human creative/accessibility review and real media sync evidence. |
| Provider, rights or customer decision delayed / high / high | No selected/authorized provider, cleared assets/fonts, legal basis or reviewer. Keep paid calls and delivery blocked; use clearly labeled procedural drafts only. |
| Capacity, schedule or external approvals uncertain / high / medium | Named roles or review windows not confirmed, holidays or scope changes occur. Re-estimate, reduce parallel work and move targets; escalate to owner rather than inventing commitments. |
| Operational recovery not demonstrated / medium / critical | Backup restore, monitoring or exact-revision smoke fails. Do not activate; rehearse rollback and resolve missing evidence before the owner decides. |
