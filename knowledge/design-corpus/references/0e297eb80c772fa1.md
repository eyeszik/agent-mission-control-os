## Selected reference evidence

### Operational visual language — source claims

Near-monochrome, content-first dashboard. Everyday actions, selected tabs, send controls, and links use neutral tones that invert between light and dark themes. Green is reserved for sparse creation CTAs, brand signature, success, and live activity. Working green uses pulse/glow while successful completion uses a static check; form distinguishes meanings sharing a hue.

Idle/present is blue; needs-user or unsaved is amber; blocked is orange; failed is red; offline is dim gray. Dense conversation badges collapse attention states into red and distinguish them with `!`, `?`, or a dot. Agent avatars retain identity hues for wayfinding. Selected conversations may use green liveness rails while selected tabs remain neutral.

### Tokens, density, and component semantics — source claims

The source places raw values in `index.css` and requires components to consume semantic tokens. Its described linter rejects ghost tokens, raw colors and sizes, retired accent families, and unsupported typography or elevation. These are reported First Tree conventions, not verified target tooling.

Colors are authored in OkLCH. App chrome uses a dense scale capped at 16px, with larger display typography reserved for marketing. Self-hosted fonts and metric-matched fallbacks support cross-platform and offline rendering. The source describes Radix and CVA primitives with a Tailwind v4 semantic layer.

Filled or bordered card chrome signifies interactivity; informational status and confirmations remain plain labeled content. Thin line icons, hairline borders, rounded-square avatars, underline tabs, aligned spacing, and a right Session sidebar support collaboration. Avoid borrowing a saturated blue primary merely because a reference uses it.
