# Contract 05 — Production Operations Contract

Core constraint: every release must have validated artifacts, traceable inputs, authentic approvals and executable recovery. Define acceptance before production. Maximum three total attempts per failed operation; never blindly retry non-idempotent actions. Escalate changed-input, authority or non-retryable failures. Record hashes, tools, cost limits and accountable/review owners. Drafting and validation do not authorize release; external actions need explicit scope. Completion requires the exact approved packet, applicable evidence and rollback owner. Missing evidence blocks release, not safe investigation.

## Required output contract

Schema notation describes types, not completed evidence.

```yaml
production_run:
  run_id: string
  brief_ref: string
  owner: string
  risk_tier: low|medium|high
  stages: [intake, policy_check, generate_or_build, validate, approve, release]
  artifacts: [{path: string, sha256: string, role: source|intermediate|release}]
  environment: {tool_versions: [string], dependency_lock_hash: string|null}
  rollback: {trigger: string, owner: string, procedure_ref: string}
```

Deliver run/index/validation/approval/rollback records. Hash actual input/policy/prompt/reference/output bytes; index source/intermediate/release roles. Runbook records review owner, approval scope, stage events and recovery target. Hashes prove integrity, not permission or quality.

## Bounded execution

Intake → policy check → generation/build → validation → approval → authorized release. Each stage needs evidence; failure enters BLOCKED with reason/owner. Mark operations RETRY_SAFE, NON_RETRYABLE or COMPENSATABLE before execution. Ambiguous remote outcomes require reconciliation before retry. Use isolated new outputs; no silent overwrite. Recovery specifies removal, reversion or replacement, its owner and response target.

Version signature tension, material logic, distinctive moves, prompts and reference abstractions. Exploration: three–five distinct routes → owner selection with rejection reasons → type/image/motion/layout system → channel assets. Record scope changes to route count. Signature/derivation scores require rubric and reviewer evidence; no global novelty claims.

## Workflow-defined metrics

Define workflow-specific SLO/error budget/RTO/RPO/cost ceiling. Measure runs, gate passes, rework/failures, approval/delivery latency, provenance, cost/accepted output and recovery. Separate creative metrics: first impression, signature, derivation concerns, accessibility equivalence and channel coherence. Unknown measurements stay unknown; logs exclude protected data.

## Completion gate

Done: hashes match, contracts pass, exact-packet approvals exist; formats/metadata/URLs/accessibility/tracking pass; rollback and creative review are recorded. Retain evidence per policy. Signoff authorizes only its stated scope, never untested compliance.

## Edge cases

1. Tool timeout after an external write: reconcile observed state; never duplicate blindly.
2. Cost/attempt ceiling reached: stop and escalate with partial artifacts and next decision.
3. Output changed after approval: invalidate affected approval and revalidate the new hash.
