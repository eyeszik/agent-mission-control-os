# Contract 01 — Brand Policy

## Objective

Translate brand strategy into controlled creative decisions. This contract defines what a release must communicate, which claims it may make, and how its visual and verbal systems behave.

## Required fields

```yaml
brand_policy:
  brand: {name: string, approved_marks: [asset_ref]}
  audience: {segments: [string], accessibility_needs: [string]}
  positioning: {category: string, promise: string, differentiation: string}
  voice: {traits: [string], approved_terms: [string], restricted_terms: [string]}
  visual_system:
    atmosphere: string
    colors: {brand: [token], neutral: [token], semantic: [token]}
    type: {display: token, body: token, data: token}
    imagery: {modes: [photo|illustration|3d|collage], treatment: string}
    composition: {grid: string, density: sparse|balanced|dense, motion: string}
  claims: [{id: string, text: string, source_ref: string, owner: string, expiry: date|null}]
  approvals: [{role: brand_owner|legal|client, decision: approved|rejected, ts_utc: RFC3339}]
```

## Controls

- Use one primary message and primary CTA per visual region.
- Assign color by role: identity, hierarchy, interaction, status, or decoration. Status always includes text or icon support.
- Define display, body, and data typography by role, scale, line height, and fallback behavior.
- Apply imagery rules for subject, crop anchor, lighting, grade, background, and treatment.
- Keep cultural references as directional evidence, never as permission to copy protected expression.
- Record claim sources, owner, applicable geography, expiry, and approval before public use.

## Aesthetic field and signature grammar

Create a distinct visual world by defining relationships, not by collecting trend labels. Every campaign, product surface, or identity system records a signature tension, silhouette, edge language, rhythm, material logic, information behavior, image direction, type behavior, and motion behavior.

Choose one tension, one material logic, and one information behavior as dominant. Supporting variables may amplify the dominant grammar only when they improve recognition, comprehension, or emotional impact. Record the reason for every intentional break from the grammar.

### Originality protocol

- Translate references into abstract attributes: contrast, density, pacing, framing, material, and semantic role.
- Compose an original combination of attributes, then test it against the supplied reference set for similarity of composition, marks, trade dress, character, and distinctive expression.
- State the novelty hypothesis in one falsifiable sentence: “This feels unlike the reference set because it combines ___ with ___ while preserving ___.”
- Treat a familiar genre as a container for a new point of view; the claim ledger and rights register remain authoritative when originality conflicts with clearance.

## Narrative architecture

| Movement | Creative function | Suitable uses |
|---|---|---|
| Arrival | Establishes atmosphere before explanation | Launch, hero, opener |
| Friction | Makes the audience notice a meaningful problem | Campaign, comparison, editorial |
| Evidence | Converts assertion into proof | Product, case study, data story |
| Participation | Makes the audience part of the visual system | Interactive UI, social, community |
| Resonance | Leaves a repeatable memory after the CTA | End card, packaging, closing scene |

## Validation

| Check | Pass condition |
|---|---|
| Brief completeness | All required fields are populated or explicitly `not_applicable`. |
| Claim traceability | Each public claim maps to an approved source or is removed. |
| System coherence | Palette, typography, imagery, layout, and motion support the stated atmosphere. |
| Channel fit | Format, CTA, reading order, and asset safe areas fit the delivery channel. |
| Brand approval | Brand owner records an approval against the exact policy version. |
| Signature integrity | The dominant tension and novelty hypothesis appear in the work without imitating a protected reference. |

## Output

`brand-policy.yaml`, `claim-ledger.csv`, approved marks/assets, and a decision record.
