# Contract 02 — Accessible UI Requirements

## Scope

Applies to web, product UI, interactive prototypes, embedded experiences, and interactive campaign surfaces. Static media must use the applicable text-alternative, caption, contrast, and motion requirements.

## Baseline

Target WCAG 2.2 AA. Treat accessibility as a release gate with automated checks plus representative manual verification.

## Requirements

```yaml
accessibility:
  semantic_structure: headings_landmarks_labels
  keyboard: logical_order|visible_focus|no_keyboard_trap
  forms: persistent_labels|clear_errors|error_recovery
  visuals: contrast_verified|color_not_sole_signal|text_alternatives
  media: captions|transcript|audio_description_assessment
  motion: prefers_reduced_motion|no_flashing|essential_feedback_preserved
  touch:
    target_size_policy: "24x24 CSS px minimum; larger where context requires"
  responsive: reflow|zoom_200_percent|orientation_supported
```

## Test evidence

| Layer | Required evidence |
|---|---|
| Automated | axe or equivalent report with zero unresolved serious/critical violations. |
| Keyboard | Tab, Shift+Tab, Enter, Space, Escape, arrows where applicable; record tested paths. |
| Screen reader | Verify representative navigation, forms, errors, dialogs, dynamic updates, and names. |
| Visual | Contrast calculations, zoom/reflow, focus visibility, and reduced-motion capture. |
| Content | Heading outline, alt-text review, captions/transcript review, plain-language error review. |

## Inclusive aesthetic direction

Accessibility strengthens a distinctive visual system when visual decisions carry meaning through more than one channel. Every Aesthetic Field declares its accessible translation: primary signal, contrast strategy, brand-consistent focus expression, reduced-motion expression, nonvisual equivalent, and cognitive-load strategy.

Use texture, typography, contour, language, and position alongside color. Treat focus as part of the visual language: it can appear as a luminous edge, a contrasting frame, or a deliberate shift in surface material, provided it remains clearly visible and meets the baseline requirements.

| Intended effect | Inclusive implementation |
|---|---|
| Cinematic reveal | Preserve the final hierarchy in a still first frame and offer motion reduction. |
| Dense editorial collage | Maintain a linear DOM order, headings, and descriptive relationships outside the collage. |
| Ambient background video | Provide captions when speech matters; retain the message without autoplay. |
| Color-rich data story | Add labels, patterns, direct values, and a table or downloadable data alternative. |
| Experimental navigation | Keep familiar names, visible location, keyboard route, and a conventional fallback. |

## Component contract

Every interactive component specifies anatomy, accessible name, keyboard model, focus behavior, default/hover/pressed/focus/disabled/loading/error states, responsive behavior, and test IDs or test path.

## Gate

Release requires a dated accessibility report tied to the artifact hash. An unresolved issue may proceed only with documented severity, user impact, owner, remediation date, and explicit approver decision.

The accessibility report records whether the intended atmosphere survives keyboard operation, 200% zoom, reduced motion, high contrast use where available, and a representative screen-reader path. A visual flourish that disappears under these conditions needs an equivalent experiential cue, such as sequence, language, sound description, or spatial grouping.
