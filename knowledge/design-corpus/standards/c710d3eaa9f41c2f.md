# Contract 02 — Accessible UI Requirements

Core constraint: target WCAG 2.2 AA through scoped automated and manual evidence; a written specification or clean scanner result is not conformance certification. Apply UI checks to interactive work and relevant alternatives/captions/contrast/motion checks to static media. Preserve keyboard access, clear focus, names, error recovery and equivalent information. Deliver a dated report tied to artifact hash. Missing checks remain untested; documented exceptions do not become passes. At most three remediation attempts, then escalate. Public release requires authorized review, not automatic document acceptance.

## Required output contract

Preserve the following requirement keys; pipe-separated entries denote a checklist, not mutually exclusive choices.

```yaml
accessibility:
  semantic_structure: headings_landmarks_labels
  keyboard: logical_order|visible_focus|no_keyboard_trap
  forms: persistent_labels|clear_errors|error_recovery
  visuals: contrast_verified|color_not_sole_signal|text_alternatives
  media: captions|transcript|audio_description_assessment
  motion: prefers_reduced_motion|no_flashing|essential_feedback_preserved
  touch:
    target_size_policy: "24x24 CSS px minimum; larger where context requires"
  responsive: reflow|zoom_200_percent|orientation_supported
```

Target size is an internal baseline; evaluate WCAG exceptions explicitly. This checklist is incomplete WCAG coverage. Record authoritative criterion/version, scope and applicability.

Components specify anatomy/name, keyboard/focus, default/hover/pressed/focus/disabled/loading/error states, responsiveness and test path. Direction specifies signal, contrast, focus, reduced motion, nonvisual equivalent and cognitive load.

## Required evidence

- Automated: axe or equivalent report, with no unresolved serious/critical violations; record tool/version/scope. Other failures still require triage.
- Keyboard: representative paths with Tab/Shift+Tab, Enter, Space, Escape and applicable arrows; include dialogs and focus return.
- Screen reader: navigation, forms/errors, dialogs, dynamic updates and names; record platform and assistive technology.
- Visual/content: calculated contrast, zoom/reflow, focus, reduced motion, heading/alt-text/caption/transcript and error-language review; record untested conditions.

Pair color with labels/patterns/position. Preserve meaning without motion/autoplay; collage needs linear order; video needs applicable captions; data needs values/table equivalent; experimental navigation needs familiar names/location/keyboard fallback. Assess keyboard, 200% zoom, reduced motion, available high contrast and screen reader: preserve meaningful equivalent cues.

## Gate and completion proof

Done: dated report binds hash/scope/check/result/evidence/reviewer. Unresolved issues need severity, impact, owner, remediation date and approver decision. Exceptions remain failures, never conformance. Report evidence completeness separately from release readiness; this is a project baseline, not a universal legal determination.

## Edge cases

1. Static/noninteractive output: assess relevant media/content checks; document UI exclusions.
2. Scanner passes but keyboard/screen-reader path fails: block that gate and remediate.
3. Missing device/assistive technology: mark coverage untested and escalate rather than simulate results.
